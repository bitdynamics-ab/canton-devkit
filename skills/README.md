# Canton DevKit agent skills

These six skills teach agents to use an installed `dpm localnet` or `canton-devkit localnet` CLI. Installing a skill does not install DevKit, Daml tooling, or Docker.

## Install

The [Skills CLI](https://github.com/vercel-labs/skills#readme) command is `npx skills` (plural), rather than `npx skill`. Node.js and npm are required.

List the available skills without installing:

```sh
npx skills add bitdynamics-ab/canton-devkit --list
```

Install all six into the current project for Codex and Claude Code:

```sh
npx skills add bitdynamics-ab/canton-devkit --skill '*' --agent codex claude-code
```

Install only a selected workflow:

```sh
npx skills add bitdynamics-ab/canton-devkit --skill canton-dar-upload --agent codex
```

Add `--global` to install for your user across projects. Omit `--agent` to choose agents interactively. To install from a local checkout before these files reach the remote default branch, run from the repository root:

```sh
npx skills add ./skills --list
npx skills add ./skills --skill '*' --agent codex claude-code
```

DevKit also installs its bundled skills without Node.js:

```sh
canton-devkit localnet skills list
canton-devkit localnet skills install --target codex
canton-devkit localnet skills install --target claude
```

The built-in installer defaults to Claude and preserves differing local files unless `--force` is supplied. The Web UI Agent Skills screen uses the same catalogue and installer. Choose one installation method per agent to avoid duplicate skills; the Skills CLI controls its own installation locations.

## Catalogue and scope

| Skill name (`--skill`) | Folder | Workflow |
| --- | --- | --- |
| `canton-localnet-lifecycle` | `canton-devkit-localnet-lifecycle/` | Host checks, start, health, pause, stop, teardown |
| `canton-dar-upload` | `canton-devkit-dar-upload/` | Upload, list, inspect, download, compare DARs |
| `canton-hot-deploy` | `canton-devkit-hot-deploy/` | Build-upload and continuous redeployment |
| `canton-inspect-contracts` | `canton-devkit-inspect-contracts/` | Contract and transaction inspection |
| `canton-token-flow` | `canton-devkit-token-flow/` | Local token creation, minting, transfer, burning, balance |
| `canton-ci-localnet` | `canton-devkit-ci-localnet/` | Disposable CI networks and guaranteed cleanup |

Keep these as separate skills. They have distinct activation triggers and operational constraints: a ledger inspection request should load party-visibility guidance, while CI needs version pinning and always-run teardown. DAR upload and hot-deploy share deployment commands, but package inspection and a persistent watch loop remain different tasks. Small amounts of shared instance setup do not justify loading every workflow for every request. Install all six when you need the full development loop; there is no required load order.

## Source and regeneration

The skills are authored in `internal/skills/docs/*.md`, not generated by an LLM at runtime. Go embeds these documents into `internal/skills`; `List()` exposes them to the CLI and Web UI, and `Install()` writes each document to `<filename-without-extension>/SKILL.md`.

This directory is a checked-in export of that catalogue for repository-based skill discovery. Edit the source documents, then regenerate from the repository root:

```sh
make skills
go test ./internal/skills ./internal/cli/localnet ./internal/ui/handlers
```

`make skills` copies the source documents into `skills/canton-devkit-<filename-without-extension>/SKILL.md`, overwriting exported copies. Folder prefixes do not change the frontmatter skill names used by `--skill` or the built-in installer's folder names. Commit source changes and their regenerated exports together. When removing or renaming a source document, also remove its obsolete export: regeneration does not prune directories. The parity test catches missing, extra, and changed exports; the existing CLI lint checks skill command examples against the actual Cobra commands and flags.
